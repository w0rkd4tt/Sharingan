Sharingan — Architecture

Hệ thống audit bảo mật source code dạng multi-agent loop. Coordinator điều phối specialist agents chạy song song, Primitive Cache ghép bug đơn lẻ thành chain, Memory Store giữ trạng thái xuyên session.

Kiến trúc tổng thể

Coordinator ở trung tâm, specialist agents xung quanh, Primitive Cache ở giữa cho mọi agent đọc/ghi.

Thay đổi cốt lõi so với pipeline tuyến tính

✕ Pipeline cũ
  • 5 phase chạy tuần tự, không quay lại
  • Một model chạy hết, context bị đầy
  • Bug tìm riêng lẻ, không ghép chain
  • State mất sau compact
✓ Sharingan v3

Agent Roster

Mỗi agent tạo một lần, dùng lại mọi session. Model được cấu hình khi tạo agent — không gán cứng.

coordinator coordinator
Nhận target repo, lập kế hoạch audit, phân công specialist agents, chạy chain scan trên Primitive Cache, quyết định quay lại phase nào, tổng hợp kết quả, trigger reporter khi đủ điều kiện.
send_to_agent list_agents memory web_search bash read
recon specialist · read-only
Xoá rác (slim_target), xác định ngôn ngữ (route_skills), quét mọi entry point (surface_map), kéo advisory cũ, tách prior/off-prior, boot runtime nếu có Docker, giao git log với surface. Incremental mode: khi coordinator gọi lại ở vòng sau, chỉ scan delta (file mới/sửa từ lần recon trước dựa trên git diff hoặc mtime) thay vì chạy lại toàn bộ. Deep entry discovery: ngoài grep/glob, phân tích framework config (router files, decorator registry, middleware chain) để tìm entry point không theo convention.
bash read glob grep web_search
normalize specialist
Polyglot loop: coordinator spawn normalize riêng cho mỗi ngôn ngữ phát hiện bởi recon (Python, JS, Go, Java…). Mỗi lần parse AST/tree-sitter → functions.jsonl, merge vào catalog chung. Sink labeling hai tầng: (1) bảng sink tĩnh theo ngôn ngữ cho known patterns, (2) infer sink động từ data flow — wrapper function quanh eval/exec, ORM method nhận raw SQL, custom serializer đều được gắn nhãn. Bảng sink cập nhật liên tục qua các vòng hunt khi hunter phát hiện sink mới.
bash code_execution read write
graph specialist · persistent thread
Xây 4 đồ thị (reachability, data flow, lifecycle, contract) từ functions.jsonl. Hoạt động như tool server — trả lời query từ coordinator và hunters. Thread giữ sống xuyên hunt.
bash code_execution read grep
hunter specialist · spawnable ×N
Agent duy nhất được ghi finding. Coordinator spawn nhiều instance song song — mỗi instance nhận slice riêng (family/component) + hunt mode (cold/variant/chain). Scope isolation: mỗi hunter nhận file boundary rõ ràng, chỉ ghi finding trong scope — vượt scope → ghi suggestion cho coordinator thay vì tự hunt. Real-time cache read: hunter đọc Primitive Cache liên tục để tránh duplicate (dedup by path_line) và biết primitive mới từ hunter khác. Oracle protocol: chọn oracle theo primitive class (canary cho file_read, race cho race_condition, parser_diff cho deser, fuzz cho input validation), timeout cấu hình per-class, fail → ghi oracle_ran:false kèm failure_reason, không retry tự động.
bash read grep memory web_fetch
reporter specialist
Không tìm bug mới. Đọc candidates + chain findings từ Primitive Cache, chạy novelty_check (GHSA/OSV), gắn stamps (M/D/E), chạy critic, tính CVSS, đóng gói disclosure nếu đủ điều kiện.
web_search web_fetch bash read memory

Coordinator Agent Loop

Vòng lặp liên tục — coordinator quyết định hành động tiếp theo dựa trên trạng thái thực.

Main Loop — Coordinator Thread

1. Nhận target

User gửi repo. Coordinator tạo session, mount repo, gắn memory store (nếu session trước đã hunt repo này → primitives và hunt_state sẵn sàng).

2. Recon

Spawn recon trong thread riêng. Ghi surface.jsonl, routing.json, advisories.jsonl, budget.json vào filesystem chung. Lần đầu: full scan. Vòng sau: incremental — chỉ scan delta (git diff / mtime) và merge vào surface.jsonl hiện tại. Deep entry discovery phân tích framework config, decorator registry, middleware chain để bắt entry point ngoài convention.

3. Normalize (polyglot loop)

Coordinator spawn normalize riêng cho mỗi ngôn ngữ phát hiện bởi recon — chạy song song. Mỗi instance parse AST/tree-sitter → functions.jsonl riêng, merge vào catalog chung. Sink labeling hai tầng: bảng tĩnh + infer động từ data flow. Bảng sink được cập nhật liên tục khi hunter phát hiện custom sink mới.

4. Graph

Spawn graph. Xây 4 đồ thị, trả targets.jsonl. Thread giữ sống — hunters sẽ query sau.

5. Chain scan + lập kế hoạch hunt

Đọc Primitive Cache từ vòng/session trước. Constraint-aware matching: không chỉ match class name qua chains_to, mà xét constraint thực tế — file_read bị giới hạn /data/ không thể đọc /etc/app.conf → loại khỏi candidate. Chia thành slices: chain-hunters + regular hunters. Priority scoring: chain candidate xếp theo severity tiềm năng × (1/constraint_count) × auth_level_inverse. Đảm bảo ≥20% slices thuộc off_prior (không chỉ ≥1).

↻ Mỗi vòng lặp bắt đầu lại từ đây — primitives mới → chain candidates mới

6. Fan-out hunters ×N

Spawn N threads song song, mỗi thread có file boundary rõ ràng. Chain-hunters xác nhận chain end-to-end. Regular hunters tìm primitive mới, đọc cache trước khi ghi để dedup (cùng path_line → skip, ghi suggestion thay vì duplicate). Hunter phát hiện target ngoài scope → ghi suggestion cho coordinator. Oracle chọn theo class: canary (file_read), race (race_condition), parser_diff (deser), fuzz (input validation) — fail ghi oracle_ran:false + failure_reason.

↻ Real-time broadcast: khi hunter ghi primitive mới → tất cả hunter khác thấy qua cache read → coordinator check chain candidates ngay → có thể spawn chain-hunter giữa vòng

7. Thu hoạch

Đọc primitives + chain findings. Coverage đủ? Chain candidate còn chưa thử? Family chưa close? Primitive mới? Nếu chưa xong → quay lại bước 5.

↑ Quay lại bước 5 nếu chưa đủ — dừng khi: hết budget, hoặc không còn chain candidate + tất cả family đã close, hoặc 2 vòng liên tiếp không primitive mới

8. Report

Spawn reporter. Novelty check, stamps, critic, CVSS, đóng gói.

9. Outcome evaluation

Outcome rubric: M∧D∧E đủ? Novelty pass? Critic EMPTY? Đạt → close + xuất report. Không → ghi RESIDUAL kèm primitives chưa ghép để session sau tiếp tục.

State Management

Ba tầng, mỗi tầng giải quyết một vấn đề khác nhau.

Primitive Cachexuyên session
Collection "primitives" trong memory store. Mỗi primitive = một khả năng đơn lẻ kèm chains_to. Tồn tại giữa các session — vòng hunt sau đọc primitive từ vòng trước để ghép chain.
Memory Storexuyên session
hunt_state (nhãn READ/INFERRED/ASSUMED), budget tracking, family status, refuted hypotheses. Ground truth nằm ngoài context → compact không làm mất.
Context Editingtrong session
Server tự xoá tool results cũ và thinking blocks đã dùng. Mỗi thread có context riêng → không nhiễu lẫn nhau.
Compactiontự động
Khi thread dài quá context window → server tự tóm tắt. Memory store giữ ground truth ngoài context nên compact an toàn.

Primitive Cache & Chain Builder

Cache tập trung mọi primitive qua các vòng hunt, để vòng sau ghép chúng thành chain có severity cao hơn.

Bài toán: Hunter A tìm được file-read, Hunter B tìm được secret-in-config — nhưng không biết nhau. Kết quả: hai bug Medium riêng lẻ thay vì một chain Critical. Primitive Cache giải quyết bằng cách cho mọi hunter ghi vào một store chung kèm trường chains_to để coordinator ghép cặp.

Cấu trúc một Primitive

{ "id": "prim_a3f8c1", "class": "file_read", // loại primitive "path_line": "src/utils/download.py:142", "entry": "GET /api/export?file=", "auth": "user", // mức auth cần "capability": "read arbitrary file on server", "constraint": "path must start with /data/", "oracle_ran": true, "oracle_type": "canary", // canary|race|parser_diff|fuzz "failure_reason": null, // null nếu pass, string nếu fail "confirm_tier": "docker-validated", "hunter_id": "thread_hunt_cold_02", "session": "session_001", "chains_to": ["secret_read", "ssrf"], // gợi ý chain tiếp "chained_from": [], // gốc — chưa thuộc chain nào "stamp": { "M": true, "D": true, "E": true } }

Quy tắc Cache

  • BẮT BUỘC Mỗi primitive trong chain phải có oracle_ran: true riêng. Không ghép primitive chưa xác nhận cơ chế.
  • BẮT BUỘC Chain-hunter phải chạy PoC end-to-end. Output bước 1 là input bước 2, trong cùng một lần thử. Oracle xác nhận toàn bộ chain.
  • BẮT BUỘC chains_to chỉ chứa lớp primitive đã biết: file_read, file_write, secret_read, ssrf, sqli, rce, deser, idor_read, idor_write, stored_xss, auth_bypass, race_condition, path_traversal, open_redirect.
  • BẮT BUỘC Dedup trước khi ghi: hunter đọc cache, check path_line trùng. Cùng path_line + cùng class → skip. Cùng path_line + khác class → ghi bình thường (cùng dòng code có thể là nhiều loại bug).
  • BẮT BUỘC Constraint-aware chain matching: coordinator xét constraint thực tế khi ghép cặp. Primitive A constraint "path must start with /data/" + Primitive B cần đọc /etc/ → loại khỏi candidate. Không match chỉ dựa trên class name.
  • NÊN Coordinator ưu tiên chain candidate theo priority score: severity tiềm năng × (1/constraint_count) × auth_level_inverse. Chain ít constraint + auth thấp = ưu tiên cao.
  • NÊN Hunter ghi chains_to ngay khi tìm được primitive. Coordinator có thể spawn chain-hunter song song giữa vòng. Các hunter khác thấy qua real-time cache read.
  • NÊN Hunter phát hiện target ngoài scope → ghi suggestion. Không tự hunt, ghi vào cache field "suggestions" để coordinator phân phối lại cho hunter đúng scope.
  • KHÔNG Coordinator không tự ghép chain. Chỉ phát hiện candidate + xét constraint. Chain-hunter mới đọc code, xây PoC, chạy oracle.
  • KHÔNG Không ghép primitive từ hai repo khác nhau. Cache thuộc một target repo.
  • KHÔNG Chain finding không thay thế primitive gốc. Cả hai vẫn tồn tại. Chain là entry mới với chained_from trỏ về gốc.
  • KHÔNG Oracle fail không retry tự động. Ghi oracle_ran:false + failure_reason. Coordinator quyết định retry ở vòng sau với config khác hay skip.

Bất biến giữ lại

Nguyên tắc cốt lõi không đổi — chỉ cơ chế thực thi khác.

  • ✓Model nói "vulnerable" ≠ bằng chứng. Oracle phải ran:true.
  • ✓Thiếu cạnh trong graph ≠ an toàn. Graph trả "không tìm thấy" → RESIDUAL, không PASS.
  • ✓Report không đi tìm bug. Reporter không có grep/code_execution cho source.
  • ✓≥1 family ngoài thiên kiến. Coordinator kiểm tra budget trước khi spawn.
  • ✓Family chưa close = chưa thử. Memory store có trường closed per family.
  • ✓Nhãn READ/INFERRED/ASSUMED. Giờ trong memory store, cùng ngữ nghĩa.

Bất biến mới

  • +Coordinator không tự hunt. Chỉ lập kế hoạch, phân công, tổng hợp. Grep sink = vi phạm.
  • +Graph sống xuyên hunt. Thread không terminate — hunters query bất kỳ lúc nào.
  • +Mỗi hunter thread = context riêng + file boundary. Không nhiễu lẫn nhau. Vượt scope → suggestion, không tự hunt.
  • +Outcome rubric thay kiểm tra thủ công. M∧D∧E là rubric criteria. Grader độc lập.
  • +Primitive Cache cho phép chain xuyên hunter/session. Mỗi primitive kèm chains_to. Coordinator ghép cặp → chain-hunter xác nhận end-to-end.
  • +Chain phải có oracle end-to-end. Hai primitive riêng lẻ đều oracle_ran:true chưa đủ — chain-hunter phải chạy PoC nối liền cả chuỗi.
  • +Session budget giới hạn chi phí. Gần hết → tổng hợp kết quả hiện có, không spawn thêm.
  • +RESIDUAL kèm chains_to. Primitive chưa ghép được → ghi RESIDUAL để session sau tiếp tục chain.
  • +Dedup by path_line trước khi ghi cache. Cùng path_line + cùng class = duplicate → skip. Tránh N hunter ghi cùng bug.
  • +Constraint-aware chain matching. Coordinator xét constraint thực tế khi ghép cặp, không chỉ class name. Chain bất khả thi bị loại trước khi spawn hunter.
  • +Recon incremental. Vòng sau chỉ scan delta (git diff / mtime). Full rescan chỉ khi coordinator yêu cầu rõ ràng.
  • +Normalize polyglot loop. Mỗi ngôn ngữ = một normalize instance. Sink labeling = bảng tĩnh + infer động, cập nhật liên tục.
  • +Oracle protocol per-class. Mỗi primitive class có oracle type + timeout riêng. Fail → oracle_ran:false + failure_reason, không retry tự động.
  • +Hunter broadcast qua cache. Hunter đọc cache real-time → biết primitive mới từ hunter khác → tránh duplicate + phối hợp ngầm.
